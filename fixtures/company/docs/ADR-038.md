# ADR-038: Session Store Migration to Redis

- **Status:** Superseded by ADR-042
- **Date:** 2026-09-22
- **Deciders:** Arjun Mehta, Priya Sharma, Meera Patel
- **Decision ID:** DEC-017
- **Ticket Ref:** LIN-391

## Context
Postgres row locks on user session records during checkout surges have caused significant latency spikes, driving p99 latency above 80ms. Redis offers in-memory sub-millisecond lookups and native key expiry TTLs, allowing us to drop session retrieval times to <5ms.

## Decision
We will migrate all active user session persistence from the Postgres `user_sessions` table to a managed Redis cluster with a default TTL of 24 hours.

## Consequences
- P99 session lookup latency drops from 80ms to <5ms.
- Session storage is now memory-bound and depends on Redis cluster stability.
- Relies on Redis eviction policies (`volatile-lru`).
