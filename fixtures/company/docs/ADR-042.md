# ADR-042: Session Store Stays on Postgres (Supersedes ADR-038)

- **Status:** Active (Supersedes ADR-038)
- **Date:** 2026-10-12
- **Deciders:** Priya Sharma, Arjun Mehta, Meera Patel
- **Decision ID:** DEC-021
- **Ticket Ref:** LIN-409
- **Supersedes:** DEC-017 (ADR-038)

## Context
Following Incident INC-77 on 2026-10-02, a memory spike caused Redis key eviction to drop approximately 12% of active checkout sessions, resulting in customer logouts and checkout abandonment. Emergency PR #1184 reverted session reads and writes back to Postgres with unlogged tables and connection pooling.

Performance benchmarks confirm Postgres with connection pooling and unlogged tables achieves acceptable p99 latency (11ms) without risk of silent session drops.

## Decision
Sessions are stored in Postgres permanently. ADR-042 ratifies PR #1184 and formally supersedes ADR-038. Redis is strictly restricted to transient idempotent rate-limiting keys and will never be used for authoritative session state.

## Consequences
- Session state is protected by ACID durability and persistent storage.
- P99 latency is stabilized at ~11ms.
- Supersedes ADR-038 and retires DEC-017.
- Priya Sharma maintains the session store service architecture.
